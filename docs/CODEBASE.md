# Codebase Guide

A file-by-file reference for the Book Explorer monorepo. See the root [package.json](../package.json) for the workspace scripts that tie these together.

## Repo layout

```
bookExplorer/
  apps/
    app/          Expo app — the mobile + web client
    server/       Fastify backend — aggregates external book/author data
  packages/
    shared/       TypeScript types shared between app and server
```

The client never calls Open Library, Google Books, or (later) Wikidata directly — it only talks to `apps/server`, which does the aggregation and caching. This keeps API keys and rate-limit-sensitive calls off the client and avoids CORS issues on web.

## `packages/shared` — shared types

The single source of truth for data shapes used by both the server (producing them) and the app (consuming them). No build step yet — both TypeScript (server, via `tsx`) and Metro (app) read the `.ts` source directly.

| File | Purpose |
|---|---|
| [package.json](../packages/shared/package.json) | Package manifest for `@book-explorer/shared`. `main`/`types` point straight at `src/index.ts` (raw TS, no compiled `dist/`). |
| [src/index.ts](../packages/shared/src/index.ts) | Defines the shared book, author, work, subject, and graph zod schemas and inferred TypeScript types, plus subject helpers. `TaggedTerm` carries a label, its source badges, and an optional canonical slug; `subjectKey` deduplicates common spelling variations, and `slugifySubject(name)` reproduces Open Library's subject URL slugging. Schemas are enforced at runtime by the app's API client. `Book` represents a scanned edition with an ISBN, while `Work` and subject listings represent Open Library works. `GraphNode.type` is `"author" \| "work" \| "subject"`; `Graph.centerId` names the graph's center node. |
| [src/index.ts](../packages/shared/src/index.ts) (awards) | `awardSlug(label)` and `awardDisplayName(label)` give an award's page slug and title-cased family name; `AwardSchema`/`AwardWinnerSchema` describe an award page (winners carry `kind` of `author`/`work`/`null`). `SubjectSchema` also has `lcshUri` (default `null`, so older cached subjects still parse). |

## `apps/server` — Fastify backend

A thin aggregation layer: it fetches from external book APIs, normalizes results into the shared types, and caches them so repeated lookups (and rate-limited Wikidata SPARQL queries) don't re-hit the network every time. Route files are thin — they just call a matching function in `src/services/` and translate `null`/thrown errors into HTTP status codes. The service functions are what actually own caching, so the graph endpoint can reuse the exact same cached author/subject/work data the plain detail endpoints use, rather than re-fetching it.

| File | Purpose |
|---|---|
| [package.json](../apps/server/package.json) | Server manifest. Runs on `tsx watch` for dev (no separate compile step); depends on `fastify`, `@fastify/cors`, and the local `@book-explorer/shared` package. |
| [tsconfig.json](../apps/server/tsconfig.json) | Node-targeted TS config (`NodeNext` module resolution, ES2022 target, strict mode). |
| [src/index.ts](../apps/server/src/index.ts) | Server entry point. Creates the Fastify instance, registers CORS (any origin; methods `GET`, `HEAD`, `POST`, `DELETE`) and all the route plugins (books, authors, subjects, works, graph, search, series, path, suggest, hardcover, plus `og` when `WEB_INDEX_HTML` is set), exposes `GET /health`, opens the persistent cache when `CACHE_DB_PATH` is set and the Hardcover account store when `ACCOUNT_DB_PATH` is set (a failure to open it is logged and the account routes answer 503), and starts listening on `PORT` (default `3001`). |
| [src/cache.ts](../apps/server/src/cache.ts) | `TtlCache<T>` — an in-memory cache with a time-to-live per entry and an optional SQLite write-through tier for namespaced caches when `CACHE_DB_PATH` is configured. `.wrap(key, fetcher)` returns cached values or calls, caches, and returns `fetcher()`'s result; it also de-dupes concurrent calls for the same uncached key. Persisted keys include a schema version so cached data with stale shapes or subject slugs is ignored after a version bump. |
| [src/httpClient.ts](../apps/server/src/httpClient.ts) | `fetchWithTimeout(url, init, timeoutMs)` — every external call in `src/sources/` goes through this rather than the bare `fetch`, which has no timeout at all. Uses `AbortSignal.timeout()` plus an independent `Promise.race` backstop, since a live-reproduced stalled connection showed the abort signal alone doesn't reliably unstick a hung connection attempt. Default 15s; `wikidata.ts` passes a longer 25s for its SPARQL queries. |
| [src/secretBox.ts](../apps/server/src/secretBox.ts) | Crypto helpers for Hardcover accounts: `randomToken`, `sha256`, and `seal`/`open`, which encrypt stored tokens with AES-256-GCM using `HARDCOVER_TOKEN_KEY` (32 bytes, base64; read on each call). |
| [src/accountStore.ts](../apps/server/src/accountStore.ts) | SQLite store (`node:sqlite`, loaded only when `openAccountStore(path)` runs) for Hardcover sign-in and Open Library sessions (`createOlSession` etc.; keys and cookie sealed): short-lived pending OAuth states (10 min) and one-time handoff codes (2 min), plus sessions whose Hardcover tokens are sealed with `secretBox`. Unlike the cache, it does not swallow open errors; `index.ts` catches them. |
| **`src/routes/`** — HTTP layer only | |
| [src/routes/books.ts](../apps/server/src/routes/books.ts) | `GET /api/books/isbn/:isbn` → `bookService.getBookDetail`. 404 with an error body if not found. |
| [src/routes/authors.ts](../apps/server/src/routes/authors.ts) | `GET /api/authors/:openLibraryId` → `authorService.getAuthorDetail`. |
| [src/routes/subjects.ts](../apps/server/src/routes/subjects.ts) | `GET /api/subjects/:slug` → `subjectService.getSubjectDetail`. |
| [src/routes/awards.ts](../apps/server/src/routes/awards.ts) | `GET /api/awards/:slug` (optional `?label=`) → `awardService.getAwardDetail`. 400 on an over-long slug or label. |
| [src/routes/works.ts](../apps/server/src/routes/works.ts) | `GET /api/works/:workId` → `workService.getWorkDetail`. |
| [src/routes/graph.ts](../apps/server/src/routes/graph.ts) | `GET /api/graph/:type/:id`, `type` one of `author`/`subject`/`work`. Dispatches to the matching `graphService.build*Graph` function via a small lookup object; an unrecognized `type` returns 400 rather than falling through to a 404. |
| [src/routes/hardcover.ts](../apps/server/src/routes/hardcover.ts) | `POST /api/hardcover/connect`, `GET /api/hardcover/callback` (public, no app key), and `POST`/`GET`/`DELETE /api/hardcover/session`; all 503 unless the account feature is configured. As the signed-in user: `GET`/`POST /api/hardcover/lists`, `GET /api/hardcover/lists/:listId`, `POST /api/hardcover/lists/:listId/books`, `DELETE /api/hardcover/lists/:listId/books/:bookId`, and `GET /api/hardcover/progress/:type/:id` (reading status for a book ISBN or work id). Exports `requireUser` for routes that act as the signed-in user. |
| [src/routes/openLibrary.ts](../apps/server/src/routes/openLibrary.ts) | `POST`/`GET`/`DELETE /api/openlibrary/session` (sign in with S3 keys), and as the signed-in user `GET`/`POST /api/openlibrary/lists`, `GET /api/openlibrary/lists/:listId`, `POST`/`DELETE /api/openlibrary/lists/:listId/seeds`. 503 unless `HARDCOVER_TOKEN_KEY` and the account store are set; ids are validated at the boundary. |
| **`src/services/`** — caching + assembly, shared between a plain detail route and the graph route | |
| [src/services/bookService.ts](../apps/server/src/services/bookService.ts) | `getBookDetail(isbn)`, cached 1 hour. Calls `openLibrary.lookupByIsbn`, enriches the result, and canonicalizes its LOC/Open Library subject terms through `subjectCanon.ts`; genres remain separate and are not LCSH-canonicalized. Google Books fills missing cover/description/rating data as needed. |
| [src/services/authorService.ts](../apps/server/src/services/authorService.ts) | `getAuthorDetail(openLibraryId)`, cached 24 hours (longer than books, since Wikidata's SPARQL endpoint is rate-limited and this data rarely changes). Resolves a Wikidata QID (from `remote_ids.wikidata`, or a name-search fallback) and pulls that author's relations. No Wikidata match still returns the Open Library bio/dates with an empty `relations` array rather than failing. |
| [src/services/subjectCanon.ts](../apps/server/src/services/subjectCanon.ts) | Resolves distinct subject labels against exact LCSH authority/variant labels and maps matches to a natural display name, authority URI, and canonical slug. Its 30-day namespaced cache persists through `CACHE_DB_PATH`; failed lookups use a short TTL and lower the caller's cache TTL. At most eight lookups run concurrently. |
| [src/services/subjectService.ts](../apps/server/src/services/subjectService.ts) | `getSubjectDetail(slug)`, cached 24 hours. Fetches the Open Library subject listing, canonicalizes its name when an LCSH match exists, and unions books from up to two other matching subject slugs (deduped by work ID, primary list first). Also loads Wikidata/LCSH related concepts. `getSubjectBooks` intentionally skips canonicalization and related-concept lookups to keep path search cheap. |
| [src/services/awardService.ts](../apps/server/src/services/awardService.ts) | `getAwardDetail(slug, label?)`, cached 24 hours. Finds the award on Wikidata and returns its description and up to 40 winners, each tagged `author`/`work` from its Open Library id; an unknown award comes back empty rather than failing. |
| [src/services/workService.ts](../apps/server/src/services/workService.ts) | `getWorkDetail(workId)`, cached 1 hour, enriches Open Library data, and canonicalizes the LOC/Open Library subject terms; `getWorkLinks` stays lightweight and uses Open Library terms only. |
| [src/services/hardcoverAccount.ts](../apps/server/src/services/hardcoverAccount.ts) | Hardcover account logic behind `routes/hardcover.ts`: `accountEnabled`, `startConnect` (checks `returnTo` against the allowed prefixes), `completeConnect`, `redeemHandoff`, and session handling (`userAuthorization` refreshes tokens shortly before expiry; `lookupAuthorization` wraps it for the book and work routes, returning `null` instead of throwing; `getAccount`, `disconnect`). |
| [src/services/openLibraryAccount.ts](../apps/server/src/services/openLibraryAccount.ts) | Open Library account logic behind `routes/openLibrary.ts`: `openLibraryEnabled`, `connect`, `asUser` (runs a call with the stored cookie, logging in again once when it has expired), `getOpenLibraryAccount`, `disconnectOpenLibrary`. |
| [src/services/graphService.ts](../apps/server/src/services/graphService.ts) | Graph builders call the matching detail service and reshape its result into `{ centerId, nodes, edges }`. Full work graphs use canonical subject slugs from tagged terms with `slugifySubject(label)` as the fallback; full subject graph centers use the canonical slug returned by `subjectService`. Path-search graph builders intentionally use the cheap, non-canonicalizing link lookups. Node ids are type-prefixed. Every builder passes through `cleanGraph()`, which dedupes nodes and edges, drops self-loops, and removes dangling edges. Graph book/subject counts are capped for legibility. `buildAwardGraph(slug, label?)` centers on the award and links each winner that has a kind and Open Library id with a `won` edge. |
| **`src/sources/`** — external API clients; entity-result caching lives in services, while autocomplete may use a small in-memory cache | |
| [src/sources/openLibrary.ts](../apps/server/src/sources/openLibrary.ts) | `lookupByIsbn` calls the Read API's `GET /api/volumes/brief/isbn/:isbn.json` endpoint (the older `/api/books?bibkeys=...` endpoint was retired) for `{ title, authors, subjects, coverUrl, description }`, plus `workId` — that response has no work reference of its own, so `resolveWorkId` makes one further request to the edition record it does point to (non-fatal on failure). `getAuthor` calls `GET /authors/:id.json`. `getWork` calls `GET /works/:id.json`; since that only references authors by id, it resolves each name via `getAuthor` (logging a warning and falling back to showing the raw id as the "name" if that fails, rather than silently passing off a resolution failure as a normal result). `getSubject` calls `GET /subjects/:slug.json` for a subject's work list. Malformed entries (an author URL or work/author key that doesn't parse) are skipped with a `console.warn` rather than thrown — Open Library is a public wiki, so one odd record shouldn't take down an otherwise-good response. Also exports `USER_AGENT`, reused by `wikidata.ts`. |
| [src/sources/loc.ts](../apps/server/src/sources/loc.ts) | Parses Library of Congress MODS records and merges subject/genre terms with source badges. Subject merges can use `subjectCanon.ts` authority identity; genre merges intentionally remain separate. |
| [src/sources/locLinkedData.ts](../apps/server/src/sources/locLinkedData.ts) | Resolves LCSH authorized and variant labels via id.loc.gov suggest2, requiring exact slug equality against a label on the same authority record; near-miss headings are rejected. Also fetches SKOS broader/narrower relations and exposes the natural-order display-label helper. |
| [src/sources/googleBooks.ts](../apps/server/src/sources/googleBooks.ts) | Google Books client, used only as a fallback for `description`/`coverUrl` when Open Library doesn't have them. Calls the public `volumes` search endpoint with `q=isbn:{isbn}`. |
| [src/sources/hardcoverOAuth.ts](../apps/server/src/sources/hardcoverOAuth.ts) | Hardcover OAuth client: PKCE generation, the authorize URL, and code exchange, refresh, revoke and a `me` lookup. Token calls use plain `fetch` rather than `fetchWithTimeout` because a retried refresh would reuse a rotated-out token. Throws `HardcoverAuthRevokedError` when Hardcover revokes the grant. |
| [src/sources/hardcover.ts](../apps/server/src/sources/hardcover.ts) | `hardcoverGraphql` throws `HardcoverUnavailableError` (carrying the `status`) on a 5xx response; `routes/hardcover.ts` answers it with a 503. |
| [src/sources/hardcoverUser.ts](../apps/server/src/sources/hardcoverUser.ts) | Hardcover calls made with the user's token: `findBookId` (ISBNs to a Hardcover book id, cached for everyone), `myLists`, `listBooks` (with `booksCount`, so the app can spot a truncated list), `createList`, `addListBook`, `removeListBook` and `readingProgress`. Mutations pass `retry: false` so a timeout never duplicates a list or row. |
| [src/sources/wikidata.ts](../apps/server/src/sources/wikidata.ts) | `searchAuthorQid(name)` is the fallback path when Open Library has no Wikidata link: picks the first `wbsearchentities` candidate whose description contains a writer-ish keyword, falling back to the top result. `searchConceptQid(name)` does the reverse for subject strings — it *rejects* candidates whose description marks them as a specific film/album/episode/edition/etc rather than a general concept, returning `null` rather than guessing if every candidate is rejected. `fetchAuthorRelations(qid)`/`fetchRelatedConcepts(qid)` build a SPARQL `UNION` query and run it through the shared `runRelationQuery` helper, which collapses duplicate `(relation, QID)` rows (a Wikidata item can carry more than one Open Library ID). `UNION` rather than several `OPTIONAL` blocks avoids a cross-product blowup when an entity has many values for more than one property. `isValidQid` rejects anything that isn't a well-formed `Q123` id before it's spliced into a query string — `remote_ids.wikidata` comes from Open Library, a wiki anyone can edit, so it's untrusted input and an unvalidated value there would be a SPARQL injection vector against Wikidata's public endpoint. `searchAwardQid(name)` returns the first candidate described as an award or prize; `fetchAwardWinners(qid)` returns labelled items that won it (reverse `P166`) with their Open Library ids. |

## `apps/app` — Expo client (mobile + web)

One Expo Router codebase. `npx expo start` serves native (iOS/Android via simulator or Expo Go) and `--web` serves a browser build via `react-native-web` — there's no separate web app.

| File | Purpose |
|---|---|
| [package.json](../apps/app/package.json) | App manifest. `main` is `expo-router/entry` (Expo Router owns the app's entry point instead of a hand-written `App.tsx`). Depends on `expo-router`, `expo-camera`, `@tanstack/react-query`, `@react-native-async-storage/async-storage`, `react-native-svg` and `d3-force` (the graph explorer), `zod` (response validation in `client.ts`), and the local `@book-explorer/shared` package. |
| [app.json](../apps/app/app.json) | Expo config: app name/slug, deep-link `scheme` (`bookexplorer`), `experiments.typedRoutes` (generates TypeScript types for route paths), iOS `NSCameraUsageDescription` and Android `CAMERA` permission text, and the `expo-camera` config plugin (which injects the platform-specific camera permission strings at build time). |
| [tsconfig.json](../apps/app/tsconfig.json) | Extends Expo's base TS config with `strict: true`. |
| [metro.config.js](../apps/app/metro.config.js) | Extends Expo's default Metro config so the bundler can see outside `apps/app` — `watchFolders` includes the monorepo root and `resolver.nodeModulesPaths` includes the root `node_modules`, which is what lets Metro resolve the workspace-linked `@book-explorer/shared` package. Without this, Metro would only look inside `apps/app` and fail to find it. |
| [expo-env.d.ts](../apps/app/expo-env.d.ts) | Auto-generated by Expo; provides ambient types for Expo's environment. Not hand-edited. |
| [AGENTS.md](../apps/app/AGENTS.md) / [CLAUDE.md](../apps/app/CLAUDE.md) | Shipped by the official Expo template, not written for this project specifically. They tell AI coding assistants to check the version-pinned Expo docs (`docs.expo.dev/versions/v57.0.0/`) before writing Expo code, since the SDK moves fast. `.claude/settings.json` alongside them enables Expo's official Claude Code plugin. |
| **`app/` — Expo Router routes** (file path = URL/screen path) | |
| [app/_layout.tsx](../apps/app/app/_layout.tsx) | Root layout, wraps every screen. Sets up the `QueryClientProvider` (React Query) used by every detail screen's data fetching, and declares the `Stack` navigator with seven screens: `index`, `scan` (presented as a modal), `book/[isbn]`, `author/[id]`, `subject/[slug]`, `work/[id]`, and `graph/[type]/[id]`. |
| [app/index.tsx](../apps/app/app/index.tsx) | Home screen, one scrolling page: eyebrow, heading and intro, a "Scan a book" button (routes to `/scan`), a boxed search field (a valid ISBN opens the book, anything else searches), "See where a thread leads" with `HomeThread`, then "Recently looked at" (cover/title rows on a thread, with `chip` filters; refreshes on focus), the feedback banner and the footer. |
| [app/scan.tsx](../apps/app/app/scan.tsx) | Camera screen. Uses `expo-camera`'s `CameraView` with `barcodeScannerSettings` restricted to book-barcode formats (`ean13`, `ean8`, `upc_a`, `upc_e`). Handles the not-yet-granted permission state with a "Grant Permission" button. On a successful scan, navigates to `/book/[isbn]` with the decoded barcode value and uses a ref (`hasScanned`) to make sure a single scan doesn't fire the navigation twice. |
| [app/book/[isbn].tsx](../apps/app/app/book/%5Bisbn%5D.tsx) | Book detail screen. Reads the `isbn` route param, fetches it via React Query (`fetchBookByIsbn`), and renders cover/title/authors/description/subjects. Each author name links to `/author/[openLibraryId]`; each subject tag links to `/subject/[slug]`. A "View as Graph" button (shown when `openLibraryWorkId` resolved) opens `/graph/work/[id]`. Records the ISBN into recent history (`addRecentIsbn`) once the fetch succeeds. Shows a spinner while loading and an error message (from the server's error body, if present) on failure. |
| [app/author/[id].tsx](../apps/app/app/author/%5Bid%5D.tsx) | Author detail screen. Reads the `id` (Open Library author ID) route param, fetches it via `fetchAuthor`, and renders name/dates/bio, then one section per relation type (Influenced by, Influenced, Notable Works, Literary Movement), skipping empty sections. Only `influencedBy`/`influenced` entries that carry an `openLibraryId` are tappable — they push a new `/author/[id]` route, so you can drill from author to author. A "View as Graph" button (shown when there's at least one relation) opens `/graph/author/[id]`. If Open Library had no Wikidata match, shows a note instead of failing outright. |
| [app/subject/[slug].tsx](../apps/app/app/subject/%5Bslug%5D.tsx) | Subject detail screen. Reads the `slug` route param, fetches it via `fetchSubject`, and renders the subject name/work count, a "View as Graph" button (`/graph/subject/[slug]`), then "Broader topics"/"Narrower topics" chip rows (tappable — each re-slugifies the concept's Wikidata label and navigates to *that* `/subject/[slug]`, which may or may not exist on Open Library; the 404 state handles a miss), then the list of related books, each tappable into `/work/[openLibraryWorkId]`. Renders as a `FlatList` (books in the list, everything else in `ListHeaderComponent`) rather than a `ScrollView`, since the book list can run to dozens of entries. |
| [app/award/[slug].tsx](../apps/app/app/award/%5Bslug%5D.tsx) | Award detail screen. Reads `slug` (and an optional `label`), fetches it via `fetchAward`, and lists the winners grouped by `groupWinners` (authors, works, others), with a "View as Graph" button and skip links. |
| [app/work/[id].tsx](../apps/app/app/work/%5Bid%5D.tsx) | Work detail screen — effectively `book/[isbn].tsx`'s counterpart for a work with no specific ISBN in hand (the case when arriving from a subject listing). Reads the `id` (Open Library work ID) route param, fetches it via `fetchWork`, and renders cover/title/authors (linking to `/author/[id]`)/description, a "View as Graph" button (`/graph/work/[id]`), then subjects (linking to `/subject/[slug]`) — this is what closes the loop back from "related book" to "its own subjects," so you can keep walking book → subject → book → subject. |
| [app/graph/[type]/[id].tsx](../apps/app/app/graph/%5Btype%5D/%5Bid%5D.tsx) | The force-directed graph explorer. Reads `type`/`id`, fetches the `Graph` via `fetchGraph`, and lays it out with `d3-force` run *synchronously* to a resting position (300 `simulation.tick()` calls with the simulation stopped, rather than animating frame-by-frame) since these graphs are small enough to converge instantly — this avoids needing an animation loop at all. Renders the result as `react-native-svg` `<Circle>`/`<Line>`/`<Text>` elements, colored by node type. Tapping a non-center node re-centers the graph on it (pushes a new `/graph/[type]/[id]`, so you drill deeper); tapping the highlighted center node instead opens its full detail screen (`/author/[id]`, `/subject/[slug]`, or `/work/[id]`). A node with `navigable: false` (an author known only by Wikidata QID) is shown dimmed and ignores taps. |
| **`src/` — non-route application code** | |
| [src/api/client.ts](../apps/app/src/api/client.ts) | Typed fetch wrapper around the server. `resolveApiBaseUrl()` picks the right host automatically: `localhost:3001` on web, or — on a physical device/simulator — the same LAN IP Metro is already running on (read from `Constants.expoConfig.hostUri`). `getJson` is the shared request helper behind every `fetch*` function; it runs the response through the matching zod schema from `@book-explorer/shared` with `.safeParse()` rather than just type-asserting the JSON, so a response that doesn't actually match the expected shape fails loudly as an `ApiError` instead of silently propagating a malformed object into a screen. |
| [src/components/SkipLink.tsx](../apps/app/src/components/SkipLink.tsx) / [src/skipLink.ts](../apps/app/src/skipLink.ts) | Web-only keyboard skip links: `SkipLink` is hidden until focused, and pressing it calls `focusSkipTarget`, which focuses and scrolls to the `SkipTarget` (an invisible, focusable `View`) that follows a long list. Both render nothing off web; `skipTargetId(name)` builds the shared element id. |
| [src/subjectIdentifiers.ts](../apps/app/src/subjectIdentifiers.ts) | `subjectIdentifiers(subject)` lists where a subject comes from (Open Library slug, LCSH heading from `lcshUri`, Wikidata item) as `{ source, id, url }` rows, omitting missing sources. |
| [src/relationHref.ts](../apps/app/src/relationHref.ts) | `relationHref(relation)` returns the page an author-page relation row opens: the award page for awards, a work or author page for notable works and influence entries with an Open Library id, otherwise `null` (plain text). |
| [src/listServiceLabels.ts](../apps/app/src/listServiceLabels.ts) | `listServiceLabels(service)` returns the sync, unlink and copy button labels for "Hardcover" or "Open Library". |
| [src/awardWinners.ts](../apps/app/src/awardWinners.ts) | `groupWinners(winners)` splits an award's winners into `authors`, `works` and `others` (no kind), keeping order. |
| [src/toolbarMetrics.ts](../apps/app/src/toolbarMetrics.ts) | `TOOLBAR_CONTROL_HEIGHT` (46), the outer height of the Graph/List control, which the graph toolbar's Filter and Share controls match. |
| [src/navigation.ts](../apps/app/src/navigation.ts) | `routes.book`/`author`/`subject`/`work`/`graph` — one function per screen, each returning an Expo Router `Href` in its typed object form (`{ pathname: "/subject/[slug]", params: { slug } }`). Also exports `nodeHref` and `nodePressHref(nodeId, centerId)`, which gives where pressing a graph node goes: genre, editions and award nodes and the center node open their page, and `null` means recenter the graph on it. |
| [src/components/TermsSection.tsx](../apps/app/src/components/TermsSection.tsx) | Renders editable/read-only subject and genre chips. Read-only subject chips navigate with the canonical slug on `TaggedTerm` when available; otherwise they fall back to `slugifySubject(label)`. |
| [src/components/PressableRow.tsx](../apps/app/src/components/PressableRow.tsx) | The shared full-width row: ≥44pt, tinted press/hover (via `rowFeedback`), focus ring, bottom rule, and a `trailing` slot the caller fills with a chevron (in-app) or external-link icon (off-app). No `onPress` renders it disabled. Used by My Library and `FindLinkRow`. |
| [src/components/Skeleton.tsx](../apps/app/src/components/Skeleton.tsx) | `Skeleton` (a pulsing block, still under reduced motion) and `DetailSkeleton` (cover, title and body placeholders with a "Loading" label), shown by the four detail screens on first load. |
