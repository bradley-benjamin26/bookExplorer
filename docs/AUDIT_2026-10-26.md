# Codebase Audit — 2026-10-26

Audit of the whole repo at commit `a39ef15` (main). Every screen, component, helper, source and service file was read, plus `app.json`, `eas.json` and the Metro config. Tests and typecheck passed: 168 app tests, 182 server tests.

**What this repo does:** Book Explorer is an Expo app for iOS, Android and web. You scan or type a book's ISBN (its barcode number) and it shows the book, its authors, its subjects and a graph linking them. You can save books to a local library, add notes and tags, and import a Goodreads export. A small Fastify server collects the data from Open Library, Wikidata, the Library of Congress, Hardcover and Google Books, and caches it. Saved data stays on the device.

**Load assumed:** a small public deployment: one server process, a handful of users at once, and some users importing Goodreads libraries of several hundred books.

## Must fix

### 1. Junk catalog notes stop the real description from loading
[apps/server/src/services/bookService.ts:69](../apps/server/src/services/bookService.ts#L69)

- **What this is:** A book page asks Google Books for a description only when it doesn't already have one.
- **Problem:** Open Library's "notes" field often holds catalog leftovers like "USA/CAN". The comment above this line says notes should not count as a description, but the code counts them. A book with a cover, a rating and notes of "USA/CAN" shows "USA/CAN" as its description, and Google Books is never asked.
- **Fix:** Change `!(wikipedia?.text ?? ol.description)` to `!wikipedia?.text`. One line.
- **If we skip it:** Many scanned books show catalog leftovers instead of a summary.

### 2. The Google Books API key ends up in server logs
[apps/server/src/sources/googleBooks.ts:15-18](../apps/server/src/sources/googleBooks.ts#L15-L18), [apps/server/src/httpClient.ts:151](../apps/server/src/httpClient.ts#L151)

- **What this is:** The server puts its Google Books key in the request URL.
- **Problem:** A timeout error message includes the full URL, and that message is logged. The secret key is then stored in plain text wherever the host keeps its logs.
- **Fix:** Send the key as a header instead: `{ headers: { "X-goog-api-key": apiKey } }`. Google's APIs accept it there.
- **If we skip it:** Anyone who can read the logs can use the key and burn through its quota.

### 3. The offline cache stops loading on Android once a library gets big
[apps/app/src/queryCache.ts:11](../apps/app/src/queryCache.ts#L11), [apps/app/src/queryCache.ts:27-52](../apps/app/src/queryCache.ts#L27-L52)

- **What this is:** The app keeps all fetched book data as one stored value. Android can't read one value larger than about 2 MB.
- **Problem:** The size limit never removes saved items. A library of a few hundred imported books goes past 2 MB. After that, every launch starts with an empty cache, offline mode shows nothing, and the whole library is downloaded again.
- **Fix:** Store each saved item under its own key, the way `savedBooks.ts` already does. TanStack Query's per-query persister does this.
- **If we skip it:** The users with the biggest libraries lose offline access entirely.

### 4. "Influenced by" links to books open an error page
[apps/app/app/author/[id].tsx:132-139](../apps/app/app/author/%5Bid%5D.tsx#L132-L139)

- **What this is:** The author page lists who influenced the author, and each entry opens as an author.
- **Problem:** Wikidata also lists *books* as influences. The server code documents a real example: Tolkien → "Beowulf" (`OL16287028W`, a work id). The author page opens it with `routes.author(...)`, and the server answers "not an Open Library author id". The graph screen already handles this case correctly, using the id's last letter (`W` = work, `A` = author).
- **Fix:** Open `routes.work(id)` when the id ends in `W`, and `routes.author(id)` otherwise.
- **If we skip it:** Tapping a classic-work influence on famous authors shows an error.

### 5. The "System" theme never follows dark mode on phones
[apps/app/app.json:9](../apps/app/app.json#L9)

- **What this is:** The app offers System, Standard and Dark themes. "System" reads the phone's setting through `useColorScheme`.
- **Problem:** `app.json` sets `"userInterfaceStyle": "light"`. This tells iOS and Android that the app is always light, so `useColorScheme` always reports light. A phone in dark mode with "System" selected still shows the light theme. Web is not affected.
- **Fix:** Change it to `"automatic"`. One line. It applies from the next native build.
- **If we skip it:** The default theme setting doesn't work on phones.

### 6. Single-book scan opens an error page for price barcodes
[apps/app/app/scan.tsx:17-20](../apps/app/app/scan.tsx#L17-L20), [apps/app/app/scan.tsx:48](../apps/app/app/scan.tsx#L48)

- **What this is:** The scan screen opens the first barcode it reads as a book.
- **Problem:** It accepts UPC and EAN-8 barcodes and never checks for an ISBN. Mass-market paperbacks often carry a UPC price barcode on the cover. Reading it closes the camera and shows "not a valid ISBN". The batch scanner already gets this right with `isIsbnBarcode` and EAN-13 only.
- **Fix:** Use the same check: `barcodeTypes: ["ean13"]`, and in `handleScanned`, `if (!isIsbnBarcode(result.data)) return;` before the `hasScanned` guard.
- **If we skip it:** Scanning the wrong barcode kicks users out of the camera.

### 7. An author with no Wikidata link can get the wrong person's bio
[apps/server/src/sources/wikidata.ts:12-16](../apps/server/src/sources/wikidata.ts#L12-L16)

- **What this is:** When Open Library has no Wikidata link for an author, the server searches Wikidata by name.
- **Problem:** If no result is described as a writer, it uses the top result anyway (`?? body.search[0]`). A little-known author who shares a name with someone famous gets the famous person's Wikipedia bio, influences and pen names. The code's stated rule elsewhere is "no match beats a wrong match".
- **Fix:** Return `match?.id ?? null`. Also add "historian", "philosopher" and "scholar" to `AUTHOR_KEYWORDS`, so real non-novelist authors still match.
- **If we skip it:** Some author pages present a stranger's life story as fact.

## Should fix

### 8. CSV import keeps going while the server is throttled
[apps/app/src/backup.ts:107-108](../apps/app/src/backup.ts#L107-L108)

- **What this is:** A Goodreads import looks up one book every 1.5 seconds.
- **Problem:** A 429 or 503 response means "slow down" or "Open Library is cooling off for up to 10 minutes". The import marks the row failed and moves on, so every row in that window fails too, up to hundreds. The background prefetch already stops on these errors with `stopsPass`, so the same situation is handled two different ways.
- **Fix:** In the `catch`, if `stopsPass(err)`, stop without moving `p.next` forward and return. The existing Resume button then continues from that row.
- **If we skip it:** Large imports end with a long, false "Couldn't look up" list.

### 9. Recommendations can include a book the user already saved
[apps/app/src/recommendations.ts:129](../apps/app/src/recommendations.ts#L129), [apps/app/src/recommendations.ts:152](../apps/app/src/recommendations.ts#L152)

- **What this is:** Saved books are filtered out of recommendations by work id or by title.
- **Problem:** The title check only lowercases. The server merges duplicate Open Library records with a stronger rule that ignores "The", trailing "(…)" and punctuation. A saved "Cricket in Times Square" can come back recommended as "The Cricket in Times Square", which is the server code's own example.
- **Fix:** Move the server's `normalizeTitle` ([graphService.ts:39](../apps/server/src/services/graphService.ts#L39)) into `packages/shared`, use it in both places, and delete the local copy.
- **If we skip it:** Recommendations look broken to users with larger libraries.

### 10. The author page's Saved button goes stale and re-saves
[apps/app/app/author/[id].tsx:39](../apps/app/app/author/%5Bid%5D.tsx#L39)

- **What this is:** The page checks once, when it first opens, whether the author is saved.
- **Problem:** Save an author, open My Library, remove it, then go back. The page still says "Saved". Tapping to unsave actually saves the author again. The book and work pages avoid this by re-reading on focus.
- **Fix:** Use `useFocusEffect(useCallback(...))`, the same pattern as [book/[isbn].tsx:64-68](../apps/app/app/book/%5Bisbn%5D.tsx#L64-L68).
- **If we skip it:** Removing a saved author sometimes doesn't stick.

### 11. Series rows can link to an edition id and open an error
[apps/server/src/sources/wikidata.ts:457](../apps/server/src/sources/wikidata.ts#L457)

- **What this is:** A work page lists its series, and each row opens that work by its Open Library id.
- **Problem:** The code's own comment says Wikidata series lists include edition records. An edition's Open Library id ends in `M` (like `OL123M`), not `W`. Tapping that row asks the work route for an edition id and shows "not an Open Library work id". This is inferred from the code comment, not from a live example.
- **Fix:** Keep the id only if it is a work id: `openLibraryWorkId: /^OL\d+W$/.test(id) ? id : null`. Rows without an id already show as not tappable.
- **If we skip it:** Some series rows lead to an error page.

### 12. The book page's source choices have no test
[apps/server/src/services/bookService.ts:23-104](../apps/server/src/services/bookService.ts#L23-L104)

- **What this is:** The busiest route chooses between five sources for the cover, description and rating.
- **Problem:** No test calls `getBookDetail`, which is how finding 1 got through.
- **Fix:** Add one test with the sources mocked, as `bookEnrichment.test.ts` does. It should check that with notes only and no Wikipedia match, Google Books is asked and its description wins.
- **If we skip it:** The next change to the source fallbacks can break descriptions without anyone noticing.

### 13. The subject routes skip the input check the path route has
[apps/server/src/routes/subjects.ts:5-7](../apps/server/src/routes/subjects.ts#L5-L7), [apps/server/src/routes/graph.ts:15-18](../apps/server/src/routes/graph.ts#L15-L18)

- **What this is:** `isSubjectSlug` rejects junk before it costs upstream calls. `/api/path` uses it.
- **Problem:** `/api/subjects/:slug` and `/api/graph/subject/:id` accept any text. Each junk value costs calls to Open Library, Library of Congress and Wikidata, plus a cache row that lasts 24 hours.
- **Fix:** Return 400 when `!isSubjectSlug(slug)` in the subjects route, and add `subject: isSubjectSlug` to `ID_VALIDATORS` in the graph route.
- **If we skip it:** A script can use up the shared Open Library budget that every user's request depends on.

### 14. The graph screen mixes ~340 lines of untested layout math with the UI
[apps/app/app/graph/[type]/[id].tsx:72-410](../apps/app/app/graph/%5Btype%5D/%5Bid%5D.tsx#L72-L410)

- **What this is:** A 1,130-line screen file that also holds pure geometry: label wrapping, label placement, node separation and the force layout.
- **Problem:** That math runs during rendering and has no tests, because it is trapped in the screen file. If it throws, the whole graph screen goes blank.
- **Fix:** Move `wrapLabel` through `layoutGraph` unchanged into `src/graphLayout.ts`. Then add one test that lays out a small graph and checks that no two nodes overlap.
- **If we skip it:** Layout bugs only show up when someone opens a graph.

## Nice to have

### 16. Two small re-implementations
[apps/app/app/saved.tsx:228-238](../apps/app/app/saved.tsx#L228-L238), [apps/server/src/services/subjectService.ts:8](../apps/server/src/services/subjectService.ts#L8)

- **What this is:** The Saved screen's remove handler rebuilds `unsaveBook` by hand (`removeSaved` plus `removeSavedBook`). `NO_LCSH` is a copy of `locLinkedData.EMPTY`.
- **Problem:** If `unsaveBook` changes, removing from the Saved screen quietly behaves differently from the book page.
- **Fix:** Call `unsaveBook(item.id)` for books, and import `EMPTY` instead of `NO_LCSH`.
- **If we skip it:** Two copies to keep in sync.

### 17. The root `build:shared` script always fails
[package.json:11](../package.json#L11)

- **What this is:** A root npm script that runs `build` in `packages/shared`.
- **Problem:** That package has no `build` script, because it is used straight from TypeScript source. `npm run build:shared` errors with "Missing script".
- **Fix:** Delete the line.
- **If we skip it:** It misleads anyone setting up a deploy.

## Summary

**Verdict:** Fix 1, 2, 5 and 6 first; each is a one- or two-line change. Then fix 4 and 7, which show users wrong or broken pages, and fix 3 before encouraging large imports.

**Lean:** about -30 lines possible, with no dependencies to remove.

**Not checked:**
- **Live calls:** no upstream API was called. Two things depend on that and are unconfirmed. First, whether Open Library returns books for long Library of Congress subject chips like "England -- Social life and customs". If it doesn't, tapping one shows "No subject found". Second, the edition-id case in finding 11.
- **Device and build:** the app was not run on a device. It is unclear how production builds set `EXPO_PUBLIC_API_BASE_URL`, because `eas.json` doesn't set it. Without it a native build points at `localhost`. The server also has no production start script, only `tsx watch`.
- **Not reviewed:** test files, `theme.ts` (colors and styles only), the style blocks at the bottom of each screen, and the docs.
